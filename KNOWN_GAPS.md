# Known Gaps

This list reflects the implementation after the database-independent Phase 1 work. **UNVERIFIED** means no real PostgreSQL run has confirmed the behavior.

## Database verification — UNVERIFIED

- **UNVERIFIED — `backend/db/schema.sql`:** PostgreSQL 16 is not installed or accessible in the current workspace; the SQL has not been executed.
- **UNVERIFIED — SQLAlchemy models vs schema:** all 49 tables are generated from the SQL source and a source-regeneration test passes, but their behavior and match have not been compared with a live PostgreSQL catalog.
- **UNVERIFIED — Alembic baseline:** configuration and a baseline revision exist but no migration has been run.
- **UNVERIFIED — seed script:** code exists but has not been run.
- **UNVERIFIED — database API tests:** tests intentionally added so far do not touch a database; authentication, persistence, RBAC queries, and seed behavior lack PostgreSQL integration tests.

Do not treat database operations as working until verified on a real PostgreSQL instance.

## Application foundation

- The FastAPI app factory, environment-backed settings, JSON logging, versioned router, and liveness endpoint are implemented. The health endpoint does not test the database.
- Auth code includes Argon2 hashing, signed access/refresh JWTs, refresh-token fingerprints, login lockout logic, RBAC dependencies, and an interactive first-admin CLI. Database-backed auth behavior is **UNVERIFIED** pending PostgreSQL testing.
- The schema-derived SQLAlchemy mappings are generated by `backend/scripts/generate_models.py`. `backend/tests/test_models_source.py` checks deterministic generation and table count, not live-database compatibility.
- The seed script uses `STATE_CODES` and `DEFAULT_ACCOUNTS` plus reference units, payment methods, permissions, and roles. It is **UNVERIFIED** until run and tested against PostgreSQL.

## Remaining product scope

- No React/TypeScript frontend, PDF/print invoice output, deployment configuration, or operational backup process is present.
- Customers, suppliers, dealers, products, inventory, sales, purchases, invoicing, payments, expenses, notifications, settings, and reports are not yet exposed as complete database-backed workflows.
- Password reset/change workflows, account administration endpoints, granular audit coverage, and broader API authorization tests remain to be implemented.
- GST assumptions are documented in `backend/README.md`; this is not a legal-compliance claim and requires review by a qualified Indian tax professional.
- BEREV's official GSTIN, PAN, bank information, and other registrations must be supplied through configuration rather than invented.
